# Synthetic data dictionary

All datasets in this directory are fictional and generated by `python -m src.data.generate_synthetic_data`. Dates use ISO `YYYY-MM-DD`; task timestamps use ISO `YYYY-MM-DDTHH:MM:SS`; time-only fields use `HH:MM:SS`.

## `stations.csv`

| Field | Type | Description |
|---|---|---|
| `station_id` | string | Fictional stable station identifier, e.g. `ST001`. |
| `station_name` | string | Fictional station name. |
| `sequence` | integer | Position from the fictional corridor origin; unique and positive. |
| `km_from_origin` | number | Synthetic kilometre distance from the fictional origin; non-negative. |

## `sections.csv`

| Field | Type | Description |
|---|---|---|
| `section_id` | string | Fictional stable section identifier, e.g. `SEC001`. |
| `from_station` | string | Origin station identifier; must exist in `stations.csv`. |
| `to_station` | string | Destination station identifier; must exist in `stations.csv`. |
| `distance_km` | number | Synthetic length of the section in kilometres; positive. |
| `normal_running_time_min` | integer | Synthetic nominal traversal time; positive. |
| `minimum_block_duration_min` | integer | Minimum fictional usable block duration for the section; positive. |
| `notes` | string | Human-readable fictional infrastructure note. |

Section station order is stored from lower to higher corridor sequence. A train with `direction=DOWN` traverses the same section in reverse physical direction.

## `maintenance_tasks.csv`

| Field | Type | Description |
|---|---|---|
| `task_id` | string | Fictional unique maintenance task identifier. |
| `department` | string | Controlled value: `Engineering`, `S&T`, or `Traction`. |
| `asset_type` | string | Fictional asset category relevant to the department. |
| `section_id` | string | Section requiring work; must exist in `sections.csv`. |
| `asset_id` | string | Fictional asset identifier within a section. |
| `task_type` | string | Maintenance activity description. |
| `criticality` | string | Controlled value: `low`, `medium`, `high`, or `critical`. |
| `urgency` | string | Controlled value: `low`, `medium`, or `high`. |
| `estimated_duration_min` | integer | Required synthetic work duration in minutes; positive. |
| `earliest_start` | datetime | Earliest fictional time the task may start. |
| `deadline` | datetime | Fictional task deadline; strictly after `earliest_start`. |
| `required_resources` | string | Pipe-delimited fictional teams/equipment needed for the work. |
| `status` | string | Controlled planning-state value: `requested`, `approved`, or `deferred`. |

## `train_movements.csv`

One row represents a train occupying one corridor section. Multiple rows can form a sequential fictional journey for the same train/date.

| Field | Type | Description |
|---|---|---|
| `movement_id` | string | Fictional unique movement record identifier. |
| `train_id` | string | Fictional train journey identifier, repeated across its section movements on a date. |
| `train_type` | string | Controlled value: `passenger` or `goods`. |
| `service_date` | date | Fictional service date in the seven-day planning horizon. |
| `section_id` | string | Traversed section; must exist in `sections.csv`. |
| `entry_time` | time | Time the fictional train enters the section. |
| `exit_time` | time | Time it exits the section; strictly after `entry_time`. |
| `direction` | string | Controlled value: `UP` (increasing station sequence) or `DOWN`. |
| `priority` | string | Controlled operational-planning value: `low`, `medium`, or `high`. |
| `expected_delay_min` | integer | Synthetic expected delay at section entry in minutes; non-negative. |

## `block_availability.csv`

| Field | Type | Description |
|---|---|---|
| `block_window_id` | string | Fictional unique block-window identifier. |
| `section_id` | string | Relevant section; must exist in `sections.csv`. |
| `date` | date | Date of the candidate or unavailable window. |
| `start_time` | time | Start of the window. |
| `end_time` | time | End of the window; strictly after `start_time`. |
| `availability_status` | string | Controlled value: `available` or `unavailable`. |
| `reason` | string | Fictional planning context, such as night maintenance allowance or passenger peak protection. |

Unavailable rows deliberately preserve known no-block periods in the synthetic planning horizon. They are not real operational restrictions.
